# B68 — `sync.core` installs without the runtime

Branch `coordinator/solo-a`, commit `1da4ae1`, on top of `29af76d`.

## What changed

`sync.core` is now built as a second distribution, `sync-core`, whose only dependency is pydantic.
The runtime distribution `sync` depends on `sync-core==0.1.0` and excludes `sync/core` from its own
wheel. No file moved, no source was copied, and nothing was published.

| | |
|---|---|
| `src/pyproject.toml` | new — the `sync-core` project |
| `pyproject.toml` | workspace member, `sync-core` dependency and source, `wheel-exclude` |
| `tests/test_core_distribution.py` | new — builds the wheel, installs it alone, uses it there |
| `CONTRIBUTING.md` | the promise it already made, with the command that keeps it |
| `uv.lock` | regenerated by `uv sync` |

## Which shape, and why

**A second distribution**, not optional dependency groups.

Extras are cheaper and they do not produce the thing the milestone asks for. One distribution ships
every module whatever the extras say, so `pip install sync` without `[runtime]` gives an adapter
author a package containing `sync.graph`, `sync.forge` and `sync.remediate` — code that raises on
import because its dependencies are absent. The dependency count would fall and the SDK would still
be the whole product with holes in it. Extras also invert what `pip install sync` means: someone
installing the product by name gets a library.

The second distribution makes "an environment holding only the core distribution" a real object
that can be built and inspected, which is what the closing condition asks for.

**Its project root is `src/`.** That is unusual and it is the only arrangement that works. uv_build
refuses a module root outside the project it is building:

    Module root must be inside the project: ..\..\src

so the `sync-core` project root has to be an ancestor of `src/sync/core`, and the repository root is
already taken by `sync`. That leaves `src/`.

The conventional-looking alternative was tried and rejected on evidence rather than taste. Hatchling
at `packages/sync-core/` with `force-include = { "../../src/foo/core" = "foo/core" }` builds a wheel
correctly, and then builds this sdist:

    foo_core-0.1.0/pyproject.toml
    foo_core-0.1.0/PKG-INFO

No source. That sdist cannot produce a wheel, which makes it a broken distribution wearing a
conventional layout. The uv_build arrangement round-trips: `uv build --package sync-core` builds the
sdist and then the wheel *from* it, and both wheels below were produced that way.

`sync-core` ships `sync/core/` with no `sync/__init__.py`, so it resolves as a namespace package
without owning the `sync` name; `sync` ships the rest as a regular package. Installed together they
merge into one `site-packages/sync/`, which was checked directly rather than assumed:

    sync.core  from ...\site-packages\sync\core\__init__.py
    sync.graph from ...\site-packages\sync\graph\__init__.py
    dists: ['sync', 'sync-core']
    usage: sync [-h] {run,ingest,shapes,merge-outcome,publish-feed,feed-public-key,intake,benchmark}

### The kit runs there

`tests/test_core_distribution.py` builds the wheel, creates a bare virtualenv, installs it, and runs
a probe inside that environment. The probe imports `sync.core`, imports all five plugin protocols,
and runs `check_vendor_adapter` twice: once against a minimal conforming adapter, once against the
same adapter with `vendor_id = ""`. Both directions are asserted, because a kit that certifies
everything is indistinguishable from a kit that ran, and an isolated environment is where nobody
would notice.

It is a pytest test rather than a documented command. It costs 1.1s of call time on top of a
one-off collection cost, needs only `uv`, and writes solely into `tmp_path`.

## What is left for whoever publishes

Not done here, deliberately, and each is a decision rather than an oversight.

- **The core distribution carries no README and no bundled LICENSE.** Both live at the repository
  root, outside this project's root, and uv_build will not reach outside it — the same constraint
  that put the project root at `src/`. Apache-2.0 asks that the licence travel with the
  distribution, so publishing needs `src/README.md` and `src/LICENSE`, or a build step that places
  them. Copying `LICENSE` is the one duplication that is safe, since it never changes.
- **The version numbers move together.** `sync` pins `sync-core==0.1.0`, so a core release bumps
  both. That is the right default for two things released from one tree, and it is a choice: if the
  SDK is ever to version independently of the runtime, the pin has to loosen to a range at the same
  time, not afterwards.
- **`sync-core` and `sync` are unclaimed on PyPI as far as this task knows.** Nothing checked, and
  nothing should have.
