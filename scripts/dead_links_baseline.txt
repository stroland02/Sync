# `omit_property_at` stays because it is not the primitive `property_omit` needs: it counts
# lines from one where `omit_argument_at` counts from zero, it answers two ways where the
# remediator needs three -- "already correct" and "cannot establish" have opposite
# consequences -- and it has no spread guard. Wiring it would be an off-by-one and a
# collapsed distinction, which is worse than a baselined line.
src/sync/route/templates.py:omit_property_at

# `parse_directory` and `versions_after` read a public OpenAPI directory and answer which APIs
# exist and when each last moved. They are reachable from nothing because their consumer is
# dependency intake, which another coordinator owns and which is live as I write this. The
# alternative was to hold the module unlanded until intake exists, and unlanded work in a shared
# worktree has already been destroyed twice on this project.
#
# Deliberately not a `VendorAdapter`. The directory's `swaggerUrl` points at its own storage
# rather than the vendor's host, and a large share of entries are Swagger 2.0 needing conversion,
# so a change derived from it is a third derivation from the vendor's truth. It is good enough to
# tell a customer a declared dependency is watchable; it is not good enough to open a pull
# request. Wiring it to the remediation pipeline would be the defect, not the fix.
#
# Whoever wires intake deletes both lines in that commit.
src/sync/signals/registry_tier/directory.py:parse_directory
src/sync/signals/registry_tier/directory.py:versions_after

# The binding scorer. `score_change` generates a labelled pair, runs the indexer and the vendor
# change detector over the mutated tree, and hands what they emitted to
# `compute_binding_accuracy`; `index_sources` is the half of that a caller needs first, since the
# mutation is positional and has to be computed against the tree whose positions were indexed.
# Both replace the two `mutate.py` entries that stood here until this commit: the generator and
# the predicate its ground truth is derived from are now reached, which is what those lines said
# would retire them.
#
# This is a harness and not a pipeline stage. Nothing in a remediation run scores anything, so
# its caller is a benchmark entry point -- a `sync benchmark` subcommand reading the corpus and a
# generated pair together -- and `cli.py` was owned by another task while this was written. The
# alternative was to leave the two axes uncomputable for one more milestone, which is the
# condition `2026-07-27-sync-benchmark-gates.md` has been recording since it was written.
#
# Whoever adds that entry point deletes both lines in the commit that adds it.
src/sync/benchmark/score.py:score_change
src/sync/benchmark/score.py:index_sources
